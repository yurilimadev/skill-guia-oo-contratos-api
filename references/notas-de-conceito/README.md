# Notas de conceito (unidades de aprendizado sob demanda)

Uma nota por conceito, carregada quando a decisão precisa dela. Não é aula: é o mínimo para decidir bem, com a ponte entre o que você já sabe (procedural) e a escolha de projeto (objeto).

## Regras de cada nota

- ≤40 linhas.
- Uma frase de definição, um exemplo do domínio, a ponte procedural→objeto.
- Sempre o custo de errar e a pergunta de decisão.
- Link para uma bancada quando o conceito for difícil de aceitar no abstrato.
- O conceito mora aqui; outros arquivos apontam para cá.

## Índice

| Nota | Quando carregar |
|---|---|
| [`objeto-vs-procedural.md`](objeto-vs-procedural.md) | quando houver regra que precisa ser sempre respeitada |
| [`agregado.md`](agregado.md) | quando algo precisar mudar junto para continuar válido |
| [`invariante-politica.md`](invariante-politica.md) | quando houver regra que o negócio pode ajustar |
| [`acoplamento.md`](acoplamento.md) | quando a mudança de um pedaço arrastar outro |

## O que não vira nota

- Catálogo de padrões de projeto. Padrão entra como exemplo, dentro da decisão.
- Conceito fora do mapa de pré-requisitos ([`../pre-requisitos.md`](../pre-requisitos.md)).
- Repetição do que já está em `dominio.md` ou `objetos.md`. A nota é curta e aponta para eles.
